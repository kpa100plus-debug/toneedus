## 정책과 구현

- 미션 등록·수정·수행 신청·신청 수정은 서버에서 이메일 인증을 요구한다.
- 이메일 인증은 실명 인증 상태를 변경하지 않는다. 회원 일괄 인증 처리 없음.
- 후보 확인·실제 거래 확정은 기존 양측 신원/활동 주체 검증을 유지한다. 실제 결제·지급 비활성화 유지.
- 로그인은 미인증 회원도 가능하며, 로그인 후 인증번호를 요청한다. 가입 시 자동 발송하지 않는다.
- Google의 서버 검증된 이메일만 인정하며, 연결된 계정의 현재 이메일과 제공업체 이메일이 일치해야 한다. NAVER는 별도 이메일 인증.
- Brevo 기존 발송 설정 재사용. 6자리 안전한 난수, 10분 유효, 목적·회원·이메일·세션별 HMAC-SHA256, 60초 재발송 간격, 5회 오입력 제한.
- 계정/IP별 발송 및 확인 제한은 성공/실패 모두 집계한다. 데이터베이스 조건부 갱신으로 동시 소비·재발송을 제한한다.
- 발송 API가 성공해야 SENT로 전환하며 실패나 제한은 명시적으로 안내한다. API 요청은 10초 제한.
- EMAIL_OTP_SECRET(32자 이상)을 설정하면 전용 HMAC 키로 사용한다. 없으면 기존 BREVO_API_KEY를 목적 구분된 HMAC에 사용한다. 어떤 키도 클라이언트로 전송하지 않는다.
- 이메일 변경은 기존 주소 OTP로 10분 재확인 권한을 얻고, 새 주소 OTP까지 확인한 뒤 변경한다. 다른 세션과 기존 비밀번호 재설정 링크를 무효화한다. 관리자 이메일 변경은 별도 운영 절차로 제한한다.
- 기존 링크는 원래 주소에만 유효하며, 신규 OTP 발급 시 무효화된다.
- 내 클리어·인증 관리·이용방법·신뢰안전·약관 안내의 인증 단계를 구분했다.
- 작성/신청/수정 내용은 회원별 임시 보관 후 원래 화면에서 다시 검토하도록 한다. 자동 제출하지 않는다.
- v63 카드 CSS 및 실제 거래·권한 보호 코드는 보존한다.

## 검증과 범위

`npm run version:sync && npm run bundle:pack && npm run prepare:source && npm test`

기존 행위·출시·기관 연동 회귀 검증과 작성 내용 복귀 DOM 검증을 수행했다. 신규 OTP 검증은 격리된 SQLite 및 모의 Brevo만 사용한다.
신규 검증에는 미설정/발송 실패, 회원·세션 간 격리, 5회 오입력, 만료, 재발송, 재사용, 재로그인, 등록·수정·신청·신청 취소, 거래 차단, 기존/새 이메일 재확인, 다른 세션 해제, 중복 확인, 요청 제한을 포함한다.

실제 수신 주소가 지정되지 않아 운영 인증메일은 발송하지 않았다. 실제 메일 도착·실제 OTP 완료는 미검증이다. 일반 회원에게 테스트 메일을 보내거나 운영 회원을 허위 인증하지 않았다.
모바일 입력 형식과 DOM 동작은 검증했으나, 현재 제공된 브라우저에는 화면 폭 조절 기능이 없어 모바일 실기기 렌더링은 미검증이다.
운영 발송 설정 여부는 최고관리자 인증 심사 화면에서 값 없이 확인한다. 설정 여부만으로 Brevo 발신자/도메인 승인이나 메일 도착이 검증된 것은 아니다.
