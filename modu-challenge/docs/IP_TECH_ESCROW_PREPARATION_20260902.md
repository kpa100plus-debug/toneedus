# 모두의 챌린지 — 특허·기술임치 준비자료

## 1. 발명의 명칭(초안)

**위험 신호 기반의 챌린지 게시 사전검토 및 관리자 승인 제어 방법, 장치 및 컴퓨터 프로그램**

영문 초안: *Risk-Signal-Based Pre-Review and Administrator Approval Control for Challenge Publication*

## 2. 해결하려는 문제

공개형 의뢰·챌린지 서비스는 보상금, 자유 서술 내용, 성공조건을 함께 받는다. 이때 고액 보상, 개인정보 노출, 연애·만남, 의료·법률, 위험행동, 불명확한 성공조건은 운영자 확인이 필요할 수 있다. 단순 차단은 정상 이용자의 표현을 과도하게 제한하고, 모든 게시물을 수동 검토하면 운영 부담이 크다.

## 3. 핵심 구성

1. 제목·요약·상세내용·성공조건·보상금 수신
2. 사전 정의된 위험 신호군 분석
   - 고액 보상금(현재 50만원 이상)
   - 개인정보·직접 연락수단
   - 연애·소개·만남
   - 의료·법률
   - 위험·불법 가능성
   - 모호한 성공조건
3. 감지 사유를 코드와 사람이 읽을 수 있는 문구로 기록
4. 감지된 경우 게시물은 삭제하지 않고 `REVIEW` 및 비공개 상태로 저장
5. 최고관리자만 사유를 확인하고 승인 가능
6. 승인 시 원래 신청한 공개 범위로 전환하고, 승인자·승인시각·감사 기록을 남김
7. 감지되지 않은 일반 챌린지는 기존 공개 절차로 즉시 등록

## 4. 차별 요소(검토용)

- 자동 분석 결과를 **삭제 또는 확정 판정**으로 사용하지 않고, 공개 제어와 검토 사유 제시에만 사용한다.
- 최초 공개 범위를 별도 보존해 관리자 승인 후 사용자 의도에 맞게 복원한다.
- 일반 게시물의 즉시 등록 흐름을 유지하면서 예외 항목만 비공개 검토 대기열로 분리한다.
- 게시물·이벤트·감사 로그를 분리하여 사후 검증 가능한 변경 이력을 남긴다.

## 5. 청구항 방향(초안)

1. 챌린지 입력값과 보상금에 대해 복수 위험 신호를 분석하고, 신호가 감지되면 게시물의 공개 상태를 비공개 검토 상태로 전환하며 감지 사유를 기록하는 방법.
2. 청구항 1의 방법에서, 원래 요청된 공개 범위를 별도 저장하고 관리자 승인 시 해당 공개 범위로 복원하는 방법.
3. 청구항 1의 방법에서, 감지 사유가 개인정보·관계성·의료·법률·위험행동·성공조건 모호성 및 보상금 임계값 중 하나 이상을 포함하는 방법.
4. 청구항 1의 방법에서, 감지 결과가 게시물의 자동 삭제 또는 불허 결정으로 사용되지 않고 관리자 검토 사유로만 제공되는 방법.
5. 위 방법을 수행하도록 구성된 서버, 관리자 단말, 데이터베이스 및 컴퓨터 프로그램.
